Details & installation

Customize artwork with a pre-made pack or use the EmbyTuneInArt tool to build your own.

Choose a ZIP on this computer. The server validates it and scans staged files with a supported local scanner when available. Review the pack and confirm before replacing the installed scope. If no scanner is available, explicit approval is required; scanner errors or threats block installation. Validation and scanning cannot guarantee malware-free images.

After installation choose Refresh now or Later. Genre artwork can affect both Music and Language; other packs affect their corresponding enabled categories. Refreshes can be blocked by active work or readiness.

Uploads require a flat ZIP containing only a strict tunein-artwork.json and the listed JPEG or PNG images, with matching IDs, counts and SHA256 hashes. Limits include 768 MiB per ZIP, 2 GiB expanded, 16 MiB per image and 4,096 pixels per dimension. The server needs its configured FFmpeg. See the README for the complete schema, limits, scanner requirements and troubleshooting.

Manual installation remains available: place image files and optional tunein-artwork.json in the corresponding server folder above, then refresh affected categories. Uploads require the strict manifest and archive layout documented in the README; older packs may need regeneration.

Experimental discovery imports

Discovery-time imports may make stations available sooner. The experimental bridge cannot reliably distinguish every import request from unrelated TuneIn work.

Early imports also require “Import Valid Results when catalog entries are skipped,” which is currently off. Accepting will enable both settings. This also allows ordinary refreshes to import valid results when entries are skipped; skipped entries can include whole branches and results remain Partial.

  • TuneIn entries may be incomplete, incorrect or exposed to another TuneIn request. Verification might not detect every problem; failed imports may require recovery.
  • Playlists, favorites, listening history or other references may be affected and may not be restored by rebuilding the TuneIn library.
  • Emby writes library changes to its database. No database corruption has been demonstrated, but server compatibility is unverified. Extra imports may slow other activity.

Advanced settings guide

These settings control how TuneIn finds stations, adds them to Emby and plays them. The defaults suit most libraries. Change one at a time when you have a reason, then save; settings do not start a refresh by themselves. Existing saved values are not replaced by new defaults.

Discovery limits

Max Station Count
Limits how many different stations are newly found in each main category. Repeated appearances of the same station count once. The default is 500; leave it blank for no limit. A higher number can find more stations but takes longer. Existing allowed stations can remain, so the final total may be higher.
Traversal depth limit
Limits how many folder levels the plugin follows while looking for stations, starting at zero for the main category. The default is 10. Increase it if stations are missing deep in folders; larger values may take longer. Previously saved deeper folders can remain.
Discovery deadline
Sets how long the search for stations may run, not counting the time spent adding them to Emby. The default is 12 hours. If time runs out, the refresh stops; start it again manually. Saved search progress may be reused.

Reaching the station or folder limit produces a Limited result rather than a complete search. Allowed existing entries can be retained.

Request pacing & retry

API request interval
Sets the minimum pause between requests to TuneIn. The default is 3 seconds. A longer pause reduces request frequency but makes searches slower.
Maximum rate-limit wait per refresh
When TuneIn asks the plugin to slow down, this limits the total time the refresh spends waiting for permission to try again. The default is 15 minutes. A longer wait may let a refresh recover but also delays its completion.
Consecutive HTTP 429 retries
How many times to retry in a row when TuneIn says too many requests have been made. The default is 6; zero means no retries. TuneIn's requested pauses and the total wait limit still apply.

Import behavior

Import deadline
Sets how long each transfer of discovered entries into Emby may take, including preparation and checks. The default is 24 hours. If it expires, the refresh stops; a manual retry starts the transfer from the beginning.
Import during category discovery
Off by default. This experimental option can make stations appear before the search finishes, but extra transfers can slow the refresh. Early imports require “Import Valid Results when catalog entries are skipped” and the safety acknowledgement. If that setting is off, the notice offers to enable both; accepting also allows ordinary refreshes to import valid results when entries are skipped. Skipped entries can include whole branches and results remain Partial. Save settings to apply the choice. If you later turn Import Valid Results off, early imports stop, but the acknowledged experimental bridge remains enabled until you turn off discovery imports. Its experimental method for handling changing Emby requests can mistake other TuneIn requests for the transfer and miss incomplete results. TuneIn items and references such as playlists, favorites and history may be affected. Database and server compatibility are unverified.

Back up Emby, including library metadata and TuneIn configuration, before testing.

First pass after entries
Waits until at least this many entries have been found before the first early transfer. Default: 50.
Minimum new entries between passes
After an early transfer, waits for at least this many additional entries before another. Default: 500.
Minimum growth between passes
Also requires the new entries to reach this percentage of the previous transfer's entry count. Default: 25%. Both this and the new-entry minimum must be met.
Minimum time between passes
Also requires this much time to pass after the preceding transfer. Default: 45 seconds. Increasing it reduces repeated work.
Maximum discovery-time passes per category
Limits the number of early transfers for each main category. Default: 100. The normal final transfer is separate.

Playback & diagnostics

Enable catalog identity diagnostics
Off by default. Adds extra information to help investigate unexpectedly recreated stations or slow refreshes. It uses additional resources and folder names can be private, so review reports before sharing and turn it off afterward.
Allow direct HLS playback
Off by default. Allows Emby to play some stations whose stream format cannot go through the plugin's usual relay. Emby fetches those streams without the relay's public-address checks. Enable it only if needed and you trust your network.
